The problem & the thesis

File chat is a solved-looking problem with an unsolved core: the answers are often plausible but wrong, the citations are vague, and structured data gets flattened into prose the moment it enters the prompt. The brief asks for something "accurate, fast, and trustworthy enough to compete with Copilot."

The thesis of Grounded is that trust is an architectural property, not a prompt. Three commitments drive every decision:

  • Every claim is traceable. Answers carry inline [n] markers that resolve to a file, a page, and the exact snippet used.
  • Structured data stays structured. Spreadsheet questions become SQL executed over the real data, the query is shown, not hidden. Charts are read into a data table, not left as pixels.
  • The system checks itself. A verification agent tests each sentence against its cited sources and produces a confidence score; below threshold it hedges or says "I don't know." Synthesis is barred from inventing a figure by back-calculating from a percentage.

The index, embeddings, SQL and vector store all live on the user's machine, your files and your index never leave it. The LLM is the one seam: the original brief was open-source-only, so it was built and works on a local 7B; a follow-up allowed paid keys, so it ships pointed at Claude, and LLM_PROVIDER=ollama flips it back. The abstraction in llm.py means nothing else in the system changes.

Hardware envelope

The target machine is a 16 GB laptop with no discrete GPU (Intel Core 7, CPU-only inference, no WSL2 so no Docker). Every component was picked against that budget, the architecture is textbook, only the implementations are lighter, and the whole stack is torch-free.

Layout-aware chunking

Chunks are cut on the tags the parser already produced, not fixed windows. Tables, code blocks, figures and enumerated items are never split. Each chunk is prefixed with its breadcrumb (Doc title › H1 › H2) so an isolated passage still carries context, and every chunk stores {source_file, page, section_path, kind, image_ref, ordinal}, the raw material for citations. The chunker never re-analyses layout itself.

Enumerated content (ingest/enumerate.py)

A run of four or more sequentially-numbered items (an MCQ exam, a policy's numbered clauses) is re-expanded into one list_item chunk per item, each with its ordinal, so "what's the answer to question 24?" pins exactly that chunk and can't be answered from a lexically-similar neighbour. Around that:

  • Option de-scramble: a two-column PDF option layout reads a c b d; put back in order.
  • Shared-stimulus grouping: a set introduced by "Answer Questions 24–28 based on the following line graph" becomes one semantic unit: every member carries, as shared_context, the stimulus body (the Figure 1: … caption and the chart's transcribed values) plus every sibling's stem, so any one question carries the chart the whole set depends on, independent of what retrieval happens to surface.
  • Puzzle ordinals: image number-pattern puzzles with no number of their own get synthetic ordinals continuing the main run, ordered by their position on the page.

Every pass no-ops when its pattern is absent.

Spreadsheets as data, not text

Each sheet is loaded with pandas and registered as a read-only DuckDB table. Column names are normalised to snake_case (Q3 Budget ($) → q3_budget) so LLM-written SQL never needs quoting. A synthetic table card (columns, dtypes, a 15-row preview labelled "preview only, N rows") is embedded alongside the document chunks so the router can discover "there is a table that can answer this". The card is discovery-only; the Table agent later queries the real DuckDB table directly.

Charts

A native PowerPoint chart carries its data (categories and named series) in a dedicated XML part, so _pptx_chart_element reads it exactly into a Markdown table plus a caption, with no rendering. A chart in a PDF is pixels. A geometric detector (_has_bar_chart: four or more same-width, evenly-spaced, bottom-aligned filled rectangles of varying height, since a row of equal boxes is a label strip and not bars) finds genuine chart pages and renders only those to a vision model, which returns a plain-language caption then the data table:

Why the caption matters "This chart shows Family of Apps (FoA) revenue worldwide by quarter from Q4 2022 to Q4 2024…": without it, a chunk the filing labelled FoA Revenue with rows dated Dec 31, 2024 does not retrieve for a question that says "Family of Apps revenue in Q4 2024". The caption carries the words a reader actually uses. Vision is gated (bar-chart shape, or heavily-drawn and text-light) and capped at four pages per document, so a 10-K's dozens of ruled table pages are never sent.

Built for files it has never seen

Ingestion assumes messy, arbitrary uploads. Each file is processed in isolation, one failure returns a readable error and the rest of the batch still ingests. Guard rails: size ceiling, page cap (with an in-line note), per-page try/except, password-protected detection, OCR fallback for scans, wide-table / big-sheet caps, CSV delimiter and encoding sniffing with bad-line skipping, EXIF-aware image downscaling, and a placeholder element when a document yields no text at all. Covered by tests/test_reliability.py.

Retrieval & indexing

Retrieval is hybrid by default. nomic-embed-text (served by Ollama, with asymmetric search_document: / search_query: prefixes) gives the dense vector, searched in embedded Qdrant; an in-process BM25 index, rebuilt from the Qdrant payloads on load, gives the lexical ranking. The two ranked lists are fused in application code with Reciprocal Rank Fusion (score = Σ 1/(k + rank), k = 60), a chunk ranked decently in both lists beats one ranked first in only one.

1Dense ANN search (Qdrant) & BM25 lexical search, once per router sub-querytop-k each

Scope-aware. The UI's "Restrict answers to" selection flows through as source_files: retrieval filters candidates, and the Table agent only sees, and can only query, spreadsheets in that set. Promotion: if a spreadsheet card matches search even though the router didn't ask for tables, retrieval promotes the question to table_qa anyway.

The multi-agent runtime

Orchestration is a LangGraph state machine over a typed, Pydantic-validated state object. Each agent is a pure node: it reads state, does one job, writes state, and no-ops when the router's decision makes it irrelevant. The graph is mostly linear (router → retrieval → table → synthesis → verification), then a conditional edge to a sixth agent, fallback, and END.

Synthesis does more than concatenate

A successful SQL result leads the prompt, labelled the authoritative answer. Without that step, a lone computed figure buried under prose from other files was treated as noise and refused. When the router called the question table_qa, the retrieved passages (all cross-document, spreadsheet chunks are stripped upstream) are dropped so unrelated text can't outvote the computation. When the question says "the chart" / "the graph", the top hit fixes which document's chart it means and other documents' chart chunks are dropped, because "the chart" is one chart, not four. Prose from other files always stays.

The Fallback agent, the one deliberate exception

It fires only when verification refused and the question targets a specific numbered item and that item is a multiple-choice question with no answer key (or an image number-pattern puzzle). It solves each item from the model's own knowledge FALLBACK_VOTES times and takes the majority; if the votes disagree it says so; it may answer "cannot determine confidently". For a chart-backed item it re-reads the actual saved image. The output is always labelled 🧮 not from your documents.

Conversation memory

Per session: the last four turns verbatim plus an LLM-folded running summary of everything older. Its consumer is the router's rewrite, resolving "what about the second one?" into a standalone question before any retrieval. It lives in the UI layer only; the CLI is stateless by design.

Grounding & verification

This is the part that is meant to beat the baseline.

Citations

The synthesis prompt supplies numbered context blocks and asks for an [n] marker on every factual sentence. Small models comply unevenly, so a second pass back-fills a marker onto any uncited sentence by content-word overlap with the context blocks. Each marker resolves to the chunk's stored metadata, so the UI renders file · page · snippet on click. Page-level today; the bounding box is captured at ingest and is the next wiring job.

Self-verification

For each sentence, the verification agent scores support against every source it cites, blending embedding cosine (nomic-embed) with content-word recall; a citation whose SQL query executed is treated as ground truth, with a further boost when the sentence's numbers appear in the result. This is deterministic and fast, a better fit for a CPU-only box than asking a small model to adjudicate entailment, which it does unreliably in both directions. Citations that barely match are dropped and their inline markers stripped.

Synthesis is barred from guessing

Two failure modes, both observed and both closed in the prompt: an unmarked MCQ or puzzle in the context is not an answer (restating an option is a guess, so found is set to false); and a figure must not be back-calculated from a percentage change, a growth rate, or a ratio, retrieval surfacing "revenue grew 22%" prose instead of the segment table once had the model invent the base figure, with verification rubber-stamping it.

Confidence & graceful refusal

One score (capped at 0.95) blends support coverage, citation coverage, and the top retrieval score. At or above CONFIDENCE_THRESHOLD the answer ships with a green badge; below it, it is prefixed with a low-confidence note. If the model cited nothing, or nothing checks out and retrieval was also weak, or nothing was retrieved at all, the answer is replaced with an explicit "I couldn't find this in your documents." The full per-sentence report sits in an expander.

Evaluation

A 32-item gold set (eval/gold.jsonl) runs over the synthetic corpus, 27 answerable across doc / table / code / image (including the multi-column PDF and DOCX tables), and 5 deliberately unanswerable. make eval runs it and writes eval/results.md.

Result Answerable correct 27/27 · refusal accuracy 5/5 · mean confidence 0.93 · median latency ~40–55 s/query on a local 7B (CPU), ~10–15 s on the Claude path. The synthetic corpus is deliberately clean, so a near-perfect score reads as "the pipeline is wired correctly end to end", not a hard accuracy number, the value is the harness and the adversarial refusal set.

pytest -q runs 83 unit tests (ruff + mypy clean) over the deterministic parts: parsing guardrails, HTML / Markdown handling, enumerated-list splitting, option de-scrambling, shared-stimulus and stimulus-body grouping, puzzle reading-order, bar-chart geometry, native-chart extraction, the table-scope guard, the synthesis context filters, the fallback gate and voting, routing edges.

Beyond the unit tests, the two real documents (a 30-question exam with no answer key, a 134-page 10-K) and the full synthetic corpus are hand-graded against a verified answer key, test_questions.md holds the copyable battery (PART A: 10 questions, one per format; PART B: 25 covering the exam and the 10-K, with expected answers and which rows should refuse). Several regressions this project hit surfaced only in that full battery, not the unit tests, it is part of the workflow.

Limitations & future work

  • Bare-numbers financial tables can rank below prose. A segment row like Reality Labs (17,729) (16,120) has almost no words for search to match. In the current test pass both segment figures answered correctly first try, but because the router's sub-queries are LLM-generated the outcome is not guaranteed deterministic, the correct figure when the table is retrieved, an honest decline when it isn't, never a fabricated number. The full fix (boost table chunks for numeric "value in year Y" lookups) is deferred to avoid regressing the table questions that already work.
  • Open-ended thematic questions are declined. "What are the main risks related to AI?": the answer is in the filing but spread across pages; the router doesn't flag it as a whole-section survey, so synthesis declines rather than present a partial list that looks complete. Widening the broad-question detector is the fix.
  • "The chart" is ambiguous across a multi-chart corpus. With four charts in four documents, a bare "the graph" gets answered from whichever chart ranks first, correctly, for that chart. Qualifying it resolves it.
  • One number-pattern puzzle (a 23-circle hexagon) is genuinely hard; the fallback declines rather than guess. The other three solve.
  • Latency. Router + synthesis per turn plus an embedding call; chart and puzzle questions add a vision call, up to three times for the self-consistency vote. Levers: FAST_MODE, FALLBACK_VOTES=1, a smaller router, a GPU. Token streaming is next.
  • Page-level citations, not bounding-box. The box is captured at ingest; the viewer overlay is the next step.
  • Verification is similarity-based. Robust for extractive answers; a per-citation number check and an NLI entailment check are the remaining work.
  • Enumerated-list handling keys on the item number as written, so two lists that both start at 1 in one document share ordinals.
  • Heading inference is heuristic (font-size based); a layout-aware parser would be more robust, declined for the ~2.5 GB PyTorch weight.
  • No audio / video, no web crawling. No auth or multi-tenancy: one workspace per running instance.
