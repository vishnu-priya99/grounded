Hybrid retrieval: how the two rankers get fused

score(chunk) = Σ 1 / (60 + rank)

Every chunk gets scored once per list it appears in, dense (Qdrant, meaning) and sparse (BM25, exact words), then the two scores are summed. Rank 1 in a list is worth ≈0.0164; rank 5 is worth ≈0.0154. The gap is deliberately small.

Why it matters: a chunk that's merely good in both signals beats one that's spectacular in only one, which is the entire point of running two rankers instead of trusting embeddings alone.

06

If they push on a decision

Why not Docker, or a hosted vector DB?
Target machine has no Docker/WSL2, and the original brief was open-source-only, fully local. A hosted vector DB (even a free tier) would ship your whole index off-box and need internet to work at all. The embedded Qdrant + DuckDB keep the index and the data on the machine regardless of which LLM is behind llm.py.
Why embedded Qdrant instead of your own flat numpy index?
Both work; embedded Qdrant is real production-grade ANN search with the same one-process-at-a-time constraint a numpy index avoided by construction. .grounded/qdrant/ takes an exclusive lock, the trade I made knowingly to get a real vector engine under the hood.
How do you know it isn't hallucinating?
The verification agent re-reads every sentence of the draft against exactly what it cited, computes 0.55·support + 0.20·coverage + 0.25·retrieval, and refuses outright if nothing checked out. It's a gate on the output, not a hope.
Why a 7B local model, not GPT-4-class?
The reasoning ceiling is real. It's mitigated (not solved) by strong hybrid retrieval, query decomposition, structured JSON output, and the verification gate doing work a bigger model would do implicitly. The original brief was open-source-only; a follow-up authorised paid keys, so the repo now ships on Claude behind LLM_PROVIDER=anthropic (claude-haiku-4-5 for routing/synthesis, claude-sonnet-5 for the fallback solve), and nothing above llm.py changed.
How do charts get answered? Isn't that just OCR noise?
A native slide chart's data is read straight from its XML. A PDF chart is found by a geometric detector (a row of same-width, varying-height bars) and rendered to a vision model, which returns a plain-language caption then a data table. The caption is what makes "Family of Apps revenue in Q4 2024" retrieve a chunk the filing labelled FoA Revenue. When a question names "the chart", other documents' charts are dropped from the context.
Grounded: multi-agent document chat, local-first data layer router → retrieval → table → synthesis → verification → (fallback)
